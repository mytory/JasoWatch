# Mytory Jaso Watch 개발 명세

## 1. 제품 개요

Mytory Jaso Watch는 Windows의 감시 폴더에서 새로 생성되거나 이름이 변경된 파일과 폴더의 파일명을 감시한다. 파일명 전체가 Unicode NFC 정규화 결과와 다르면, 기존 항목을 덮어쓰지 않는 이름으로 자동 변경한다.

기본 감시 폴더는 Windows가 제공하는 Downloads 알려진 폴더다. 이 조회가 실패한 경우에만 `%USERPROFILE%\Downloads`를 사용한다.

Mytory Jaso Watch는 파일 내용이나 폴더 내용은 변경하지 않는다. 파일명만 변경하며, 설치 없이 단일 EXE로 실행하는 포터블 유틸리티다.

## 2. 지원 환경과 배포

- C#, .NET 10 LTS, WinForms
- Windows 10 및 Windows 11 x64
- `win-x64` self-contained single-file publish
- 배포물은 `Mytory Jaso Watch.exe` 하나를 담은 ZIP
- v1에는 코드 서명을 포함하지 않는다.
- ARM64, 32비트 Windows, 네트워크 공유 폴더 감시는 v1 범위에서 제외한다.

## 3. 파일명 정상화

### 3.1 대상

- 감시 폴더 안의 파일과 폴더를 대상으로 한다. 감시 폴더 자체의 이름은 바꾸지 않는다.
- 하위 폴더 감시는 기본으로 켜져 있다. 사용자가 끄면 감시 폴더 바로 아래 항목만 대상이다.
- 재분석 지점(심볼릭 링크, 정션 등)은 따라가지 않는다. 감시 범위 안의 링크 자체는 이름 변경 대상이 될 수 있다.
- 숨김·시스템 속성은 제외 기준이 아니다.
- 감시 폴더 밖으로 이동된 대기 항목은 이름을 바꾸지 않고 작업을 취소한다.

### 3.2 정규화 규칙

- 파일명 전체에 `string.Normalize(NormalizationForm.FormC)`를 적용한다.
- NFC 결과가 현재 파일명과 같으면 변경하지 않는다.
- 한글만 별도로 분석하거나 조합하지 않는다.
- Unicode 표준 자모 NFD와 다른 모든 Unicode 표준 분해 문자를 NFC로 정규화한다.
- 호환 자모(`ㅎㅏㄴㄱㅡㄹ` 등)를 직접 한글로 조합하는 기능은 제공하지 않는다.

표준 자모 NFD의 예:

`한글 문서.pdf` → `한글 문서.pdf`

### 3.3 이름 충돌

- 정상화 결과와 같은 이름의 파일 또는 폴더가 있으면 덮어쓰지 않는다.
- 확장자가 있는 파일은 마지막 확장자 앞에 공백과 숫자를 넣는다.
- 폴더는 이름 끝에 공백과 숫자를 넣는다.
- 사용할 수 있는 가장 작은 양의 정수를 선택한다.

예:

`한글.pdf` → `한글.pdf`  
`한글.pdf`가 이미 있으면 → `한글 1.pdf`

- 충돌 여부는 대상 Windows 파일 시스템의 실제 이름 비교 규칙을 따른다. 일반적인 대소문자 구분 없는 Windows 볼륨에서는 대소문자만 다른 이름도 충돌이다.
- 실제 이름 변경 직전에 후보 이름의 사용 가능 여부를 다시 확인한다. 외부 프로그램과 경합으로 변경이 실패하면 충돌 번호를 다시 계산해 재시도한다.
- 충돌 계산과 실제 이름 변경은 부모 폴더별로 직렬화한다. 대기·안정성 확인은 항목별로 독립 수행한다.

## 4. 감시와 다운로드 완료 판정

### 4.1 이벤트 처리

- `Created`와 `Renamed` 이벤트를 감시한다.
- `Changed` 이벤트는 이미 정상화 대기 또는 정상화 실패 상태였던 항목의 재시도 신호로만 사용한다.
- 같은 항목에서 연속 이벤트가 오면 최신 경로 기준으로 하나의 작업으로 합치고, 새 이벤트마다 debounce를 다시 시작한다.
- 새로 들어온 폴더는 하위 폴더 감시가 켜진 경우 실제 하위 항목도 비동기로 검사한다.

### 4.2 안정성 확인

이벤트 뒤 약 1초의 debounce를 둔다. 이후 500ms 간격으로 두 번 확인해 파일 크기와 최종 수정 시각이 같고, 다른 프로세스가 잠그고 있지 않을 때만 이름을 변경한다.

아직 쓰기 중이거나 잠긴 경우 지수형 재시도를 한다. 항목 하나의 재시도 기간은 최대 10분이다. 한 항목의 대기는 다른 항목을 막지 않는다.

재시도 기간이 끝나면 해당 항목은 정상화 실패 상태가 된다. 이후 `Changed`, `Created`, `Renamed` 이벤트가 오면 다시 시도한다. 모든 실패가 해소되거나 대상이 감시 범위 밖으로 사라지면 경고 상태를 해제한다.

### 4.3 임시 파일 제외

다음 규칙에 맞는 **파일**은 자동 감시와 기존 파일명 정리 모두에서 제외한다.

- 기본 제외 확장자: `.crdownload`, `.part`, `.tmp`
- 기본 제외 파일명 접두사: `~$`
- 확장자와 접두사 비교는 대소문자를 구분하지 않는다.
- 확장자는 마지막 확장자 기준으로 비교한다. `notes.part.pdf`는 제외되지 않는다.
- 접두사·확장자 규칙은 폴더에는 적용하지 않는다.
- 사용자는 기본 규칙을 포함해 추가·삭제할 수 있으며, 기본값 복원 기능을 제공한다.

## 5. 감시 상태와 복구

### 5.1 감시 일시 중단

- 사용자가 일시 중단하면 감시기를 중지한다.
- 대기·재시도·아직 시작하지 않은 기존 파일명 정리 작업을 취소한다.
- 이미 시작한 이름 변경 하나만 안전하게 마친다.
- 중단 중 들어온 항목은 재개 시 소급 처리하지 않는다. 이후 새 이벤트만 감시한다.
- 일시 중단 상태는 앱 재시작 뒤 유지하지 않는다.

### 5.2 감시 폴더 접근 불가

- 감시 폴더가 삭제·이동·분리되거나 접근할 수 없으면 설정은 유지하고 감시를 중지한다.
- 폴더가 같은 경로에서 다시 접근 가능해지면 감시를 자동 재개한다.
- 접근 불가 중 실행되던 기존 파일명 정리는 끝낸 것으로 처리하지 않고 중단한다. 폴더가 복구돼도 사용자가 다시 시작해야 한다.

### 5.3 이벤트 유실 복구

`FileSystemWatcher` 내부 버퍼 초과 등으로 이벤트가 유실되면 감시기를 재생성하고 현재 감시 범위를 한 번 재검사한다. 이 이벤트 복구 검사는 감시 신뢰성을 위한 예외적 자동 작업이다.

앱이 종료돼 있던 동안 들어온 항목은 다음 실행 시 자동으로 소급 검사하지 않는다.

## 6. 기존 파일명 정리

- 사용자가 트레이 메뉴에서 명시적으로 시작하는 일회성 작업이다.
- 현재 감시 범위를 적용한다. 하위 폴더 감시가 켜져 있으면 실제 하위 폴더까지 검사한다.
- 임시 파일 제외 규칙을 적용한다.
- 가장 깊은 경로부터 처리하며, 각 폴더 안의 파일을 먼저 처리한 뒤 폴더 이름을 처리한다.
- 한 번에 하나만 실행한다. 진행 중에는 메뉴를 `기존 파일명 정리 중…`으로 표시하고 비활성화한다.
- 별도 확인 대화상자는 표시하지 않는다.
- 감시 자체는 정리 중에도 계속한다.
- 상태 메뉴에는 검사 수와 변경 수를 표시한다. 완료 알림은 실제 정상화된 항목 수를 중심으로 표시하고, 검사·실패 수는 괄호 안의 참고 정보로 한 번 알린다. 변경이 없으면 바꿀 파일명이 없음을 표시한다.
- 되돌리기 기능은 v1에 포함하지 않는다.

## 7. 트레이 UI

별도 메인 창 없이 Windows 시스템 트레이에 상주한다. UI와 상태 알림은 한국어로 제공한다.

### 7.1 메뉴

- 상태 표시: 실행 중, 일시 중단, 감시 폴더 접근 불가, 기존 파일명 정리 진행, 정상화 실패 수
- 감시 일시 중지 / 재개
- 기본 감시 폴더일 때 `다운로드 폴더 열기`, 사용자 지정 폴더일 때 `감시 폴더 열기`
- 기존 파일명 정리
- 설정
- 종료

트레이 아이콘을 두 번 클릭하면 현재 감시 폴더를 Explorer로 연다.

### 7.2 상태 아이콘과 알림

- 활성: 파란 기본 아이콘
- 일시 중단: 회색 아이콘
- 정상화 실패 또는 감시 폴더 접근 불가: 주황 경고 점 아이콘

개별 파일명 변경에는 알림을 표시하지 않는다. 다음 상황에만 상태 알림을 한 번 표시한다.

- 최초 실행: `트레이에서 자동 감시 중입니다. 기존 파일은 ‘기존 파일명 정리’ 메뉴에서 처리하세요.`를 한 번 표시한다. 이 안내의 표시 여부는 설정 파일에 보관한다.
- 이미 실행 중인 인스턴스를 다시 실행함
- 기존 파일명 정리 완료
- 이벤트 복구 검사 완료
- 감시 폴더 접근 불가
- 정상화 실패가 처음 발생하거나 실패 수가 증가함

아이콘 리소스는 `assets/icons/`에 둔다.

## 8. 설정

설정은 `%LocalAppData%\JasoWatch\settings.json`에 저장한다. 실행 파일 위치와 분리해 쓰기 권한 문제를 피하고 EXE 이동 뒤에도 설정을 유지한다.

설정 항목:

- Windows 시작 시 자동 실행 (기본값: 켜짐)
- 감시 폴더
- 하위 폴더 감시 여부 (기본값: 켜짐)
- 처리 제외 확장자
- 처리 제외 파일명 접두사

설정 저장 시 감시 폴더의 존재와 접근 권한을 검증한다. 성공하면 감시기를 안전하게 교체해 재시작 없이 적용한다. 실패하면 이유를 보여주고 기존 감시는 유지한다.

감시 폴더를 바꾼 직후에는 그 폴더에 이미 있던 항목을 자동으로 정리하지 않는다.

설정 파일을 읽을 수 없으면 `settings.json.bak`으로 보존하고 다음 기본값으로 시작한다.

- Downloads 알려진 폴더
- 하위 폴더 감시 켜짐
- 자동 시작 켜짐
- 기본 제외 규칙

## 9. Windows 자동 시작

- 새 설정의 기본값은 켜짐이다. 사용자는 설정에서 끌 수 있다.
- `HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run`을 사용한다.
- 값 이름은 `JasoWatch`다.
- 값 데이터는 따옴표로 감싼 현재 EXE 경로와 `--autostart` 인수다.
- 관리자 권한은 사용하지 않는다.
- `--autostart`로 시작하면 별도 알림 없이 트레이에 상주한다.
- 자동 시작이 켜진 상태에서 EXE 위치가 바뀌면, 다음 정상 실행 때 현재 경로로 Run 값을 자동 갱신한다.
- 설정상 자동 시작이 켜져 있으나 Run 값이 없어졌다면 정상 실행 시 복구한다.
- 등록 실패 시 설정은 꺼진 상태로 유지한다.
- 해제 중 삭제가 실패하면 설정은 켜진 상태로 유지하고 실패를 표시한다.

## 10. 중복 실행과 종료

- 사용자 세션마다 실행 인스턴스는 하나만 허용한다.
- 같은 세션에서 두 번째로 실행하면 새 프로세스는 즉시 종료한다.
- 기존 인스턴스는 트레이 알림으로 이미 실행 중임을 한 번 알린다.
- 사용자가 종료를 선택하면 새 작업과 대기·재시도 작업을 취소한다. 이미 실행 중인 이름 변경 하나만 안전하게 끝낸 뒤 종료한다.

## 11. 진단과 테스트

- v1에는 파일명 또는 활동을 담은 영구 로그를 남기지 않는다.
- 단위 테스트로 NFC 판정, 처리 제외 규칙, 충돌 번호 선택, 감시 범위 판정을 검증한다.
- `FileSystemWatcher`, Run 레지스트리, Mutex, 트레이 UI는 Windows 실제 환경에서 통합 또는 수동 검증한다.
